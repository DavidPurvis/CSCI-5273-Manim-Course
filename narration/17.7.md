# Dish 17.7: Practice question 7: the bootstrap trace

## 17.7.question
Practice question 7. DHCP confirms a client at 192.0.2.10/24, gateway 192.0.2.1, and DNS server 198.51.100.53. The client wants www.example.test, and all caches are empty. Outline the DHCP message order, which IP address is ARPed before the DNS query leaves, and the Ethernet and IP destinations of that query. Then explain why "DNS always happens before ARP" is misleading.

## 17.7.predict
Write the order down before going on.

## 17.7.dhcp
DHCP goes Discover, Offer, Request, ACK.

## 17.7.arp
The DNS server. 198.51.100.53 is off-link. Under a slash 24, it isn't in 192.0.2. So the client must send through its gateway, and it ARPs for the gateway, 192.0.2.1.

## 17.7.query
The query then leaves with the gateway's MAC as its Ethernet destination, and the DNS server, 198.51.100.53, as its IP destination.

## 17.7.trap
Why is "DNS always happens before ARP" misleading? Because conceptually you want the name first, but the DNS query is itself a packet. It can't leave until its local delivery dependency is met. Request order isn't packet transmission order.
