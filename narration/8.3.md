# Dish 8.3: Inside a router

## 8.3.question
A router has found the right output. Now a packet must physically cross the machine, while packets arrive on every other port too. Where can this go wrong? When a router is slow, which part is actually the bottleneck?

## 8.3.parts
A router has four main parts. Input ports receive the bits, check the link layer, and do the lookup. A switching fabric moves packets between ports. Output ports buffer and transmit them. And a routing processor runs the control plane, computing the tables that input ports use. Follow our packet: in, lookup, across, queue, out.

## 8.3.fabrics
The fabric's capacity is the first limit. With 4 inputs, each at 10 gigabits per second, up to 40 gigabits per second may be offered. A fabric that cannot move that much makes inputs wait, even when every output is free. There are three classic designs.

## 8.3.memory
The oldest design is memory switching. The packet is copied into shared memory, and then copied out again. Each packet crosses memory twice, so memory bandwidth must be double the useful throughput.

## 8.3.memory-more
Put a number on it. If a memory system can sustain 20 gigabits per second of copying, each forwarded bit is copied twice, so the router tops out near 10 gigabits per second, before any other overhead.

## 8.3.bus
Next is a shared bus. A packet crosses directly from input to output, over one internal bus. That avoids the double copy. But only one packet can use the bus at a time, so the bus speed caps the entire router.

## 8.3.bus-more
Again, a number. Four 10 gigabit inputs feed a 20 gigabit bus. They offer 40 gigabits per second, and only 20 can cross, even if every output link sits idle. The bus is the bottleneck, before the outputs are even considered.

## 8.3.crossbar
The third design is an interconnection network, such as a crossbar. Now input 1 to output 2 and input 2 to output 1 can transfer at the same moment, over separate crossing points. Clos networks build big fabrics out of small switching stages. Many of them chop packets into fixed internal cells. Those cells are an internal technique, not IP fragments.

## 8.3.crossbar-more
There's still a limit. Input 1 to output 2 and input 2 to output 1 can move together. But send both inputs to output 1, and they contend for that one output. Parallel paths inside the fabric create no extra capacity at a single output.

## 8.3.hol
Even a crossbar has a trap. If two inputs want the same output at once, one must wait. Say input B and input C both have a head packet for output 1. B wins. C's head packet stays blocked. Now look behind it. C's second packet wants output 2, and output 2 is idle. But the queue is first in, first out, so that packet is stuck behind the blocked head. This is head of line blocking. A free output sits unused because of how the queue is arranged.

## 8.3.outq
Packets can also wait at the output, and this limit is physical. Three 1,500 byte packets arrive together at a 12 megabit per second output. Each needs 1 millisecond to transmit. So they finish at 1, 2, and 3 milliseconds, after waiting 0, 1, and 2. A faster fabric can't help, because the wire has a fixed rate. If arrivals keep exceeding that rate, the buffer eventually fills, and something is dropped. A drop policy chooses what to discard. A scheduler chooses what to send next. Priority shifts who suffers, but it creates no new bits per second.

## 8.3.timescales
Step back from the queues, and look at the timescales in this machine. The data plane forwards, buffers, and schedules, in nanoseconds per packet, in line card hardware. The control plane runs routing and signaling, in tens of milliseconds to seconds per event, in router software. The management plane is people and scripts doing analysis and configuration, in minutes to hours. Tables could be typed in statically, but static entries don't adapt to failures, new equipment, or load.

## 8.3.macvsip
It's also a good moment to compare our two forwarding worlds, as the instructor's questions do. Are both MAC and IP addresses allocated hierarchically? Yes, both are: MAC blocks go to vendors, and IP blocks go down through registries. Which is organized by topology? Only IP. Which forwards by exact match? MAC, since IP uses longest prefix. Which builds its table automatically, by watching data? Ethernet switches. Which keeps per-host state in the network? MAC. Routers keep state per prefix. And which keeps per-connection state? Neither one. These answers are worked out from the lecture's material, as the slide gives no key.

## 8.3.rule
Before proposing a fix, find the contention. Is it at lookup, in the memory or bus or fabric, in an input queue, or at the output? Upgrading one simply moves the bottleneck to another.

## 8.3.pitfall
Careful with memory switching. Its internal copy rate is not its useful throughput. Each packet crosses memory twice, so useful throughput is half.

## 8.3.changed
Picture this. Ten senders all saturate one 10 gigabit output. Somebody proposes doubling the fabric speed.

## 8.3.predict
Will it help? What would a bigger buffer do instead?

## 8.3.answer
It won't. Packets just reach the same full output sooner. A bigger buffer absorbs short bursts, but under persistent overload it only adds delay before the same drops. The output's rate is the limit.
