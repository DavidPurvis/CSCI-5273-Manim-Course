# Dish 13.3: Choosing a tree

## 13.3.question
To deliver to many networks, routers need a tree. But we've already met one tree in spanning tree, and another in Dijkstra's. Are they the same? What does best even mean for a tree? And should every sender get its own tree, or should they all share one?

## 13.3.kinds
First, a split. A source-based tree is rooted at one sender, so state is kept per source and group, written S comma G. A shared tree is used by all senders in the group, written star comma G. A shared tree needs less state. Source trees can give shorter paths. So we're trading memory against path quality.

## 13.3.mst
Next, objectives. A minimum spanning tree connects all nodes with the smallest total edge cost. There are two classic ways to find one. Prim's algorithm grows one tree outward, always adding the cheapest edge that crosses from the tree to a node outside. Kruskal's algorithm sorts all edges, and adds each one unless it would create a cycle. Try this triangle: A to B is 1, B to C is 1, and A to C is 1 point 5. Both algorithms choose A B and B C, for a total of 2.

## 13.3.objectives
Ask a different question. What's the shortest way from A to C? It's the direct edge, at 1 point 5, which isn't even in that tree. Dijkstra's tree from A would use it. So three things share the word tree. STP makes layer 2 forwarding loop-free. An MST minimizes total edge cost. A shortest path tree minimizes distance from one source. Same word, different objectives.

## 13.3.core
One more design: core-based trees. Pick one router as the meeting point, called the core. Each receiver's router sends a join toward the core, and that request stops as soon as it hits a router already on the tree. Traffic then flows along those branches. It's simple and uses little state. But the core could become a hot spot, and paths may take a detour through it.

## 13.3.core-more
The sharing. Receiver routers A and B both join toward the core, and their paths merge at M. So the branch from the core to M carries one copy, and M replicates it toward the two receivers.

## 13.3.pitfall
These algorithms look alike, and they aren't. Dijkstra accumulates distance from a source. Prim just picks the cheapest edge reaching the growing tree. The resulting trees can differ.

## 13.3.changed
Change one cost. Make the direct A to C edge cost 0 point 5.

## 13.3.predict
What's the minimum spanning tree now, and its total cost? And what's the shortest path tree from A?

## 13.3.answer
The MST takes A C at 0 point 5, plus one of the edges of cost 1, for a total of 1 point 5. There's a tie, so either A B or B C works. From A, the shortest path tree uses A C and A B. So this time the two objectives can coincide, on one of the valid MSTs. They just don't have to. Real multicast protocols don't compute a global MST. They use something cheaper, already sitting in every router: the unicast routing table.
