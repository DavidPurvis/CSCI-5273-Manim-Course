# Dish 17.2: Practice question 2: collisions and loops

## 17.2.question
Practice question 2. Explain why full-duplex switching can still queue, and why redundant Ethernet links need spanning tree. Then say which problem each mechanism addresses: collision, output contention, or a flooding loop.

## 17.2.predict
Match each mechanism to its problem before going on.

## 17.2.duplex
Full duplex gives each point-to-point link its own send and receive paths, so the shared half-duplex collision contest is gone on that link. But two inputs can still want the same output at the same moment. Only one frame can leave at a time, so the other one queues. There's no collision, just contention.

## 17.2.stp
The loop. Redundant links form a cycle in the active topology. A flooded frame goes around that cycle, and Ethernet has no hop limit to stop it. Spanning tree blocks enough links that the active topology has no cycle, so flooded frames can't circulate forever.

## 17.2.trap
The tempting answer blurs these together. Full duplex does not remove queues, and spanning tree does not prevent collisions. Keep the scopes apart. Full duplex ends the collision contest on a link. Queues handle output contention. Spanning tree handles flooding loops.

## 17.2.marks
On marks: two points for output contention, two for flooding and spanning tree, and one for keeping the scopes separate.
