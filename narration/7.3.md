# Dish 7.3: The IPv4 header

## 7.3.question
What does a router actually need to read? The IPv4 header has only about a dozen fields, and each exists to solve one bounded problem. Read them by purpose and by unit, because the units are where the traps are.

## 7.3.fields
The header. Version says 4. IHL, the header length, counts 32 bit words, not bytes. So a value of 5 means 20 bytes. A packet with IHL 6 and total length 1024 therefore has 24 header bytes, and 1000 bytes of payload.

## 7.3.length
Total length counts the whole datagram in bytes, and it is a 16 bit field. So the largest value is 2 to the 16th, minus one, which is 65,535 bytes. The slide prints 63,535. That is a typo, and the arithmetic settles it.

## 7.3.protocol
The protocol field names what comes next, such as TCP, 6, or UDP, 17. It is not a port number. Follow the chain of hand-offs. Ethernet's type says this payload is IPv4. IPv4's protocol says this payload is UDP. UDP's destination port selects the program.

## 7.3.ttl
TTL limits the damage from routing loops. Every router lowers it by one, and at zero the packet dies, and the router normally sends back an ICMP time exceeded message. A clever tool turns this into a map. Traceroute sends a probe with TTL 1. The first router replies. Then TTL 2, and the second router replies. Each reply reveals one more hop. A missing reply may just mean a router declines to answer.

## 7.3.checksum
One more field is linked to TTL. The header checksum is a one's complement sum over the header only. It does not cover the payload, it does not authenticate anybody, and it cannot repair errors. And here is the consequence. Each router lowers the TTL, which changes the header. So each router must also update the checksum. With TTL 64, our example header's checksum works out to one value. With TTL 63, it is a different one.

## 7.3.rule
Read each field with its unit. IHL is in 32 bit words. Total length is in bytes. Fragment offset is in 8 byte units. TTL is in router hops. Mixing these up is how most header questions are lost.

## 7.3.pitfall
A common overclaim. The IPv4 checksum doesn't protect the payload, doesn't correct anything, and doesn't authenticate a sender. It only detects errors in the header.

## 7.3.changed
A new situation. A forwarding loop forms between R1 and R2, and a packet enters it with TTL 64. Meanwhile a DNS answer has a TTL of 300, and our switch table has a timer too.

## 7.3.predict
Does TTL rescue this packet? And do those three things called TTL all count the same thing?

## 7.3.answer
TTL does not rescue it. It only ends it, after using up link capacity, so the damage is bounded rather than prevented. And the three are different. IP's TTL counts router hops. A DNS TTL counts seconds of cache life. A switch table timer ages an entry locally. Same acronym, different arithmetic. One field group remains, those fragmentation fields, so let us use them.
