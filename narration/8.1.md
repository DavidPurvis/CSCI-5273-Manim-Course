# Dish 8.1: Carving a subnet

## 8.1.question
Our laptop's network got its addresses from somewhere. An organization holds one block, and four departments of very different sizes. How do you cut the block so that everyone fits, nothing overlaps, and routers can still describe each piece with a single prefix?

## 8.1.sizing
Start with size, not with addresses. A subnet with h host bits holds 2 to the h addresses. Two are reserved, for the network and the broadcast. So to hold H hosts, choose the smallest h where 2 to the h, minus 2, is at least H. The prefix length is then 32 minus h. Using different sizes inside one block is called variable length subnet masking.

## 8.1.borrow
To feel the trade, take one slash 24 and start borrowing host bits for subnets. Borrow 1 bit: 2 subnets, with 7 host bits left, so 126 hosts in each. Borrow 2 bits: 4 subnets of 62 hosts. Borrow 3: 8 subnets of 30. Each borrowed bit doubles the number of subnets, and roughly halves their size. Keep going, and at 7 borrowed bits, only one host bit remains. The formula then gives zero ordinary hosts. A slash 31 needs its own point to point interpretation, so don't apply the subtraction blindly there.

## 8.1.endsystem
Why does a host care about all this? Because the mask is how it makes its first decision. Before sending, it ANDs the destination with its own mask, and compares that with its own network. If they match, the destination is on this link, so it sends directly. If not, it sends to its gateway. Routers apply masks too, but to a whole table of prefixes, as we'll see in a moment.

## 8.1.parent
The instructor's example. Four departments need 130, 120, 60, and 31 hosts, inside a slash 23. The slide labels the parent 128.101.5.0/23. Apply the mask, though. A slash 23 forces the last bit of the third byte to zero, and 5 is odd. So the true network is 128.101.4.0/23. It covers third byte values 4 and 5, and the slide's department blocks fit this normalized parent.

## 8.1.largest
Allocate the largest first, since that keeps the blocks aligned. Department A needs 130. 7 host bits give only 126, so it takes 8 bits, a slash 24, the first half of the parent. B needs 120, and 7 bits give 126. That is a slash 25, at 128.101.5.0. C needs 60. 6 bits give 62, so a slash 26. D needs 31. It is tempting to pick a slash 27, because 32 addresses seem like enough. But a slash 27 leaves only 30 usable. So D also needs a slash 26.

## 8.1.bar
See the blocks laid along the parent. 256 plus 128 plus 64 plus 64 is 512, and that fills the slash 23 exactly. Each block begins on a multiple of its own size, which is what lets a single prefix describe it.

## 8.1.rule
Check any allocation three separate ways. Does each subnet have enough usable hosts? Do any overlap? And is each one contained in the parent? A plausible looking dotted address proves none of those.

## 8.1.pitfall
The mistake that looks harmless: placing a block wherever there's room. A block must begin on a multiple of its own size. Otherwise, no single prefix can describe it.

## 8.1.changed
Change one requirement. Department C's count of 60 did not include its router interface or its printers. The real requirement is 63 interfaces.

## 8.1.predict
What prefix does C need now? And does the whole plan still fit in the slash 23?

## 8.1.answer
6 bits give only 62 usable, so C jumps to 7 bits, a slash 25, with 128 addresses. Add that up: 256, plus 128, plus 128, plus 64, is 576. That is more than 512, so the plan no longer fits. A single extra host at a boundary doubled the block, which is why you must state exactly what the count includes. The result is a table of overlapping prefixes on every router, so how does a router choose among them?
