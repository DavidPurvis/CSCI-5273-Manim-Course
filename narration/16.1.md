# Dish 16.1: The whole story, then mixed problems

## 16.1.question
We began with one question. How does a packet reach the right place, when no device knows the whole path? Now we can answer it. Every mechanism in this course supplies one missing fact, keeps some state, picks one action, or contains one failure. Let's retell the entire journey, and then test it on problems that cross chapters.

## 16.1.story1
A laptop wakes up. Wi-Fi association attaches it to an access point, and a broadcast to DHCP gives it an address, mask, gateway, and resolver. Its mask says the resolver is remote, so ARP finds the gateway's MAC address. A frame carries the DNS query to R1. The resolver walks the hierarchy, using caches when it can, and returns an A record. Now the laptop can send to the server.

## 16.1.story2
The frame crosses switches, which learned their tables from source addresses. At R1 the frame is replaced, while the packet's endpoints stay fixed, and TTL drops by one. Longest prefix match selects the output. The packet crosses the fabric, waits in a queue, and leaves. Those tables came from the control plane: link state or distance vector inside an AS, and BGP between ASes, shaped by contracts, with the next hop resolved through internal routing.

## 16.1.story3
When something breaks, detection, propagation, computation, and installation all take time, and in between come blackholes and loops. If the destination is a group, IGMP learns local interest, and PIM connects the routers. If it's one of many, routing picks an instance. And when the receiver moves, a tunnel carries the same inner packet to a changing outer destination, while control messages move the endpoints. The envelope is local, and the packet is global. At each layer, the question is who knows what.

## 16.1.pitfall
Before the problems, one last trap. Exam answers go wrong when mechanisms blur together. Each one supplies one missing fact. Name the fact first, and then the mechanism.

## 16.1.p1
Mixed problems. Problem one. A host at 10.10.1.97/23 sends to 10.10.0.200. Then to 10.10.2.5. Its gateway is 10.10.0.1. Which IP address does it ARP for, each time? Think in terms of the mask.

## 16.1.a1
The block covers third byte values 0 and 1. So 10.10.0.200 is local, and the host ARPs for 10.10.0.200 itself. 10.10.2.5 is outside the block, so it ARPs for its gateway, 10.10.0.1. The mask decides, not how the numbers look.

## 16.1.p2
Problem two. A router uses distance vector. Its link to neighbor A costs 2, and A says 7. Its link to neighbor B costs 5, and B says 1. Which route wins? Then the destination fails, and B had been routing through this very router. What goes wrong, and which fix applies?

## 16.1.a2
Through A costs 9, and through B costs 6, so B wins. But wait. If B reaches the destination through this router, then B's advertised 1 could be stale, with no real path behind it. The result is count to infinity, on a two-node dependency. Poison reverse would have had B advertise infinity back to us, so that the false route would never have been considered at all.

## 16.1.p3
Problem three. Your AS has a route from a provider with local preference 80 and an AS path of length 2, and a route from a customer with local preference 100 and length 5. You pick one. Which do you use? And would you advertise the other to your peer?

## 16.1.a3
You use the customer route, because preference comes first, so path length never comes into it here. You'd advertise that customer route to your peer, since customer routes go everywhere. The provider route you would not offer to a peer, even if it were your only route, because that would make you carry traffic between two non-customers.

## 16.1.p5
Problem four. A 2,000 byte datagram, with a 20 byte header, must cross a link with an MTU of 1,500. Which bytes go in the first fragment? What offset does the second one carry? Then its destination, 201.10.6.200, meets the same three-entry table as before. Which output?

## 16.1.a5
The data is 1,980 bytes. The first fragment carries 1,480, at offset 0, with the more fragments flag set. The second carries 500, at offset 185, with the flag cleared. For lookup, 201.10.6.200 matches the slash 21, the slash 23, and the slash 0, so the slash 23 wins: output B. Each fragment gets the same lookup, since every fragment has the same destination.

## 16.1.p6
Problem five. A multicast router reaches source S through port 2. A packet from S to group G arrives on port 4, and later on port 2. Its LAN has one member, and that member sends a leave. What happens at each step?

## 16.1.a6
On port 4, the reverse path test fails, so it's dropped as a likely duplicate. On port 2, it passes, and the packet is forwarded onto interested outputs. When the member leaves, the router doesn't prune right away. It sends a group-specific query, since others might remain. When no one answers, it stops forwarding there, and if no other branches want the data, it prunes upstream. IGMP handled the LAN, and PIM handled the routers.

## 16.1.p4
Last one. A phone's tunnel runs through S-GW to base station A, and a correspondent reaches the phone's stable address. The phone hands over to base station B. Which fields change in the packet that the S-GW sends afterward?

## 16.1.predict
Name exactly what changes, and what stays the same.

## 16.1.a4
The outer destination changes, from A to B. The inner packet stays the same. That's the picture you started this course with, one final time. The blue address persists, while an outer envelope changes around it. At the very beginning it was yellow, on one Ethernet link. Now it's a tunnel across a cellular core. It's the same idea at a new scale. When you face a new mechanism, ask what's missing, who knows it, what state is kept, and what happens when that state goes stale. If you can trace one packet through it with real addresses, you understand it. Next, try the practice midterm walkthrough in chapter 13, and use the study player to answer before each explanation.
