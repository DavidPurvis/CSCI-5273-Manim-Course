# Dish 15.3: Finding a moving phone

## 15.3.question
The problem that was planted back in chapter 3. An IP address says where you are in the topology. That's what makes routing scale. So what happens when you move? Your old address now points to the wrong place. But your identity, the thing others use to contact you, hasn't changed. One number has been doing two jobs.

## 15.3.naive
One approach: let the routing system handle it. Have the phone advertise its own slash 32 from wherever it is. Routers would find it, in principle. But think about billions of devices, each changing location constantly, with each change spreading through every router in the world. That would be enormous, rapidly changing routing state. And it would destroy the very aggregation that makes routing scale. So we push the problem to the edge instead.

## 15.3.homevisited
Split the two roles. The home network is the provider you subscribe to. It always knows who you are. The visited network is wherever you currently are. It provides access, and tells your home where you've gone. This happens even between countries. In cellular, the HSS is on the home side. The generic Mobile IP example and LTE share this principle, even though the protocols and components have different names.

## 15.3.register
A constructed Mobile IP example. The mobile's home address is 192.0.2.20. On arriving at a visited network, it gets a current locator, called a care-of address, 198.51.100.44. It registers this with its home agent, which records a binding from home address to care-of address. The drawing has a foreign agent ending the tunnel. A co-located care-of address, where the mobile itself ends the tunnel, is another valid arrangement. And don't mix this generic Mobile IP up with LTE's HSS, MME, and GTP.

## 15.3.tunnel
A correspondent sends to the mobile. It uses the home address, not knowing anything has changed. The packet arrives at the home network. The home agent intercepts it, and puts the whole packet inside a new one: an outer IP header, from the home agent to the care-of address. That's IP tunneling. Routers in the middle follow only the outer header. At the far end, the outer header comes off, and out comes the original packet, with its source and destination unchanged. This is indirect routing. The correspondent never needed to know about the move.

## 15.3.size
Tunnels cost bytes. An illustrative outer IPv4 header adds 20 bytes. A 1,480 byte inner packet becomes 1,500, which just fits an Ethernet link. A 1,500 byte inner packet becomes 1,520, and that needs different MTU treatment. And don't confuse tunneling with NAT. NAT rewrites addresses. A tunnel adds an envelope.

## 15.3.move
Watch the mobile move again, to a new locator, 203.0.113.44. It re-registers. The home agent updates its binding. The outer destination changes. The inner destination stays right where it was. That's the visual to hold on to: identity in blue, unchanged, and location in the outer header, changing.

## 15.3.triangle
What's the downside of indirect delivery? A detour. Traffic goes through the home agent, even when the correspondent is right next to the mobile. This is triangle routing. In this constructed example, the correspondent to home agent takes 40 milliseconds. Then 50 more to the mobile. That's 90, while a direct path would only take 10. It's a detour, not a loop.

## 15.3.direct
Direct routing removes the detour. The correspondent obtains the current locator, then tunnels straight to it. It saves 80 milliseconds here. But the price is complexity. The correspondent must now handle bindings. And when the mobile moves again, something must handle packets aimed at the old location. Neither design removes location state. It only changes who holds and uses it.

## 15.3.pitfall
When you trace a tunnel, always say which header you mean. The outer destination changes. The inner source and destination don't. An answer that just says, the destination, is ambiguous.

## 15.3.changed
Change the geography. Correspondent to home agent is 60 milliseconds. Home agent to mobile is 70. Direct is 5.

## 15.3.predict
What's the one-way delay with each design? And if the correspondent is actually beside the home agent, does the triangle still hurt?

## 15.3.answer
Indirect is 130 milliseconds, and direct is 5. But if the home agent is near the path anyway, the detour shrinks to nothing. It depends on geometry. Now one piece remains. All of this assumed a phone that has already arrived somewhere. What about the moment of moving itself, in the middle of a video, from one tower to another?
