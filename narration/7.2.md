# Dish 7.2: Addresses and prefixes

## 7.2.question
A switch can keep one table entry per machine, because a LAN is small. The Internet holds billions of interfaces. If every router needed an entry for every one, no router could cope. So how can a router in another country forward a packet toward your laptop without ever having heard of it?

## 7.2.address
An IPv4 address is simply a 32 bit number, written as four decimal bytes. Here is our example, 10.10.1.97. It identifies an interface, not a computer, so a router with three links has three addresses. And unlike a MAC address, this one has structure.

## 7.2.prefix
The structure is this. The leading bits name a network, and the trailing bits name a host within that network. The boundary is written after a slash. In 10.10.1.97/23, the first 23 bits are the network part, leaving 9 bits for hosts. A router far away only needs to know which way to send that whole block. Every host inside is covered by one entry. That is how the Internet scales.

## 7.2.classful
Originally that boundary was forced. Classful addressing offered only three unicast sizes: slash 8, slash 16, and slash 24. An organization needing 300 addresses was too big for a slash 24, so it received a slash 16, with 65 thousand addresses, and wasted nearly all of them.

## 7.2.classful-more
The class was even written into the address's first bits. An initial zero meant class A, one zero meant class B, and one one zero meant class C. Class D, beginning one one one zero, is multicast. Today the prefix is stated explicitly, so a first byte no longer implies a mask.

## 7.2.cidr
CIDR, classless inter-domain routing, lets the boundary fall anywhere. Now the 300 address organization takes a slash 23, with 512 addresses. Each bit you add to the prefix halves the block. A slash 24 has 2 to the 8th, which is 256. A slash 23 has twice that. CIDR also allows aggregation. Two halves of one slash 24 can be announced as that single slash 24. But two ranges that merely look close may not combine, because a block must be aligned on its own size.

## 7.2.allocation
Who hands out these blocks? Allocation is hierarchical too. ICANN allocates to regional registries. Those allocate to Internet providers and large institutions, who pass smaller blocks on to their customers. So 12.0.0.0/8 might contain 12.3.0.0/16, which contains 12.3.1.0/24. A provider can then announce one short prefix for all of its customers together. The address hierarchy mirrors the business hierarchy, and it's what keeps routing tables manageable. Compare that to a switch, whose table lists individual machines.

## 7.2.mask
To compute with a prefix, write it as a subnet mask. That is 32 bits with ones over the network part, and zeros over the host part. A slash 23 is 255.255.254.0. Now apply it. A bitwise AND of address and mask keeps the network bits, and clears the host bits. The result is the network address, 10.10.0.0. Notice what happened in the third byte. The 1 was cleared, because that last bit belongs to the host part.

## 7.2.broadcast
Do the opposite. Set every host bit to one, and you get the broadcast address of this subnet, 10.10.1.255. The all zeros and all ones host patterns are reserved. So this block has 512 addresses in total, and 510 usable ones, from 10.10.0.1 through 10.10.1.254.

## 7.2.rule
That subtraction of two applies to ordinary subnets. A slash 31 point to point link and a slash 32 host route need their own interpretation, so do not apply it blindly. The real rule is this. An address alone tells you nothing about its subnet. You need the mask.

## 7.2.pitfall
A tempting shortcut is to compare the first three bytes of two addresses. That only works for a slash 24. For any other prefix, apply the actual mask.

## 7.2.changed
A trap on purpose. In this same slash 23, consider the address 10.10.0.255. It ends in 255.

## 7.2.predict
Is it a broadcast address? Look at the host bits, not at the decimal number.

## 7.2.answer
No. Its host part is 0 11111111, and that first zero means the bits are not all ones. It is an ordinary host address, sitting in the middle of the block. The ending 255 only signals broadcast when the mask says the last byte alone is the host part. So the numbers are only half of the picture, and the other half is the header that carries them.
